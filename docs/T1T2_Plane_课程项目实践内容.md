# **软件体系结构课程项目实践 T1-T2**选题项目

本项目参考 GitHub 开源项目 Plane，设计一个简化版的团队项目管理与缺陷跟踪系统。

项目网址：https://github.com/makeplane/plane

选择理由：

1.  Plane 是较热门的开源项目管理平台，GitHub 页面显示约 50.1k stars、4.4k forks，并且最近版本为 2026 年 5 月 14 日发布的 v1.3.1。
2.  Plane 的业务边界清晰，核心功能包括 work items、cycles、modules、views、pages、analytics 等，适合抽象为中等复杂规模的软件系统。
3.  系统涉及多人协作、任务流转、权限控制、富文本编辑、附件、统计分析、部署运维等内容，能够覆盖可用性、性能、安全性、可修改性、可扩展性等软件体系结构质量属性。
4.  后续 T3-T6 可选择实现其简化版本，例如只实现工作空间、项目、任务、看板视图、评论和统计看板，规模可控。

# 推荐项目介绍

Plane 是一个开源的项目管理与产品研发协作平台，定位上接近 Jira、Linear、Asana 等工具，但更强调开源、自托管和面向软件团队的研发流程管理。它的核心对象是工作空间、项目、工作项、迭代周期、模块和多种视图，团队可以围绕需求、缺陷、任务和版本计划进行协作。

从软件体系结构课程实践角度看，Plane 很适合作为参考项目。首先，它的业务场景真实且边界清楚，既有用户、权限、项目、任务等基础模块，也有看板、列表、迭代、统计、通知等协作功能。其次，它天然包含多个质量属性问题，例如多人并发访问带来的性能要求、项目数据隔离带来的安全性要求、任务视图扩展带来的可修改性要求，以及系统自托管部署带来的可部署性和可维护性要求。因此，基于 Plane 做一个简化版 MiniPlane，能够较好覆盖 T1-T7 的完整实践链路。

本项目拟设计的系统命名为“轻量级团队项目协作与缺陷跟踪系统”，面向课程实践时可简称为 MiniPlane。

# T1 软件系统需求

## 1\. 系统背景

中小型软件开发团队在日常研发中需要管理需求、缺陷、任务、迭代计划和项目进度。传统 Excel 或即时通讯工具难以持续追踪任务状态、负责人、优先级、历史评论和整体进度。MiniPlane 旨在提供一个 Web 化项目协作系统，使团队能够在统一工作空间内完成项目管理、任务流转、迭代管理和进度分析。

## 2\. 用户角色

|                |                                                            |
| -------------- | ---------------------------------------------------------- |
| **角色**       | **说明**                                                   |
| 系统管理员     | 负责系统配置、用户管理、工作空间初始化和全局权限维护。     |
| 工作空间管理员 | 负责某一团队工作空间的成员、项目、角色和配置管理。         |
| 项目负责人     | 负责创建项目、规划迭代、拆分模块、分配任务并查看项目统计。 |
| 普通成员       | 负责创建、领取、编辑和评论任务，更新任务状态。             |
| 访客/只读成员  | 只能查看被授权项目和任务，不能修改核心数据。               |

## 4\. 非功能性需求

|          |              |                                                                                                 |
| -------- | ------------ | ----------------------------------------------------------------------------------------------- |
| **编号** | **质量属性** | **非功能性需求**                                                                                |
| NF1      | 性能         | 在 100 名并发在线用户、10 万条任务数据规模下，常用页面查询响应时间不超过 2 秒。                 |
| NF2      | 可用性       | 系统核心服务月可用率不低于 99.5%，单个 Web 服务实例故障时应能在 1 分钟内恢复访问。              |
| NF3      | 安全性       | 用户密码必须加密存储，未授权用户不能访问工作空间和项目数据。                                    |
| NF4      | 可修改性     | 新增一种任务视图或任务字段时，应尽量不影响用户、权限、通知等已有模块，开发工作量不超过 3 人日。 |
| NF5      | 可扩展性     | 系统应支持从单机部署扩展到前后端分离、多实例服务和独立数据库部署。                              |
| NF6      | 易用性       | 普通成员应能在 5 分钟内完成“登录、进入项目、创建任务、更新状态”的基本流程。                     |
| NF7      | 可维护性     | 代码应采用分层结构，接口、业务逻辑和数据访问职责分离，便于测试和维护。                          |
| NF8      | 数据可靠性   | 任务、评论、权限、操作日志等关键数据应持久化保存，异常退出后不应丢失已提交数据。                |
| NF9      | 可测试性     | 用户登录、任务创建、任务流转、权限校验等核心功能应能通过自动化测试验证。                        |
| NF10     | 可部署性     | 系统应支持 Docker 或类似方式快速部署，普通测试环境部署时间不超过 30 分钟。                      |

## 4\. T2 小结

通过用例分析可以看出，MiniPlane 的核心业务集中在“工作空间-项目-任务-迭代”的协作链路上。功能需求主要关注用户如何创建、分配、推进和追踪任务；非功能需求则主要关注系统在多人并发、权限隔离、数据可靠、后续扩展和快速部署方面的质量属性。上述分析结果可作为后续 T3 架构设计、T4 ATAM 评价、T5 编码实现和 T6 测试的输入。
